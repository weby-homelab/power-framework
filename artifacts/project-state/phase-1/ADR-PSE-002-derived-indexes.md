# ADR-PSE-002: Secondary Projections, Derived SQLite Indexes, and Rebuildability

- **Status:** ACCEPTED
- **Date:** 2026-09-03
- **Deciders:** POWER Architecture Guild, Weby Homelab
- **Context:** While the append-only event ledger (`events.jsonl`) provides unmatched durability and auditability, querying relational structures, RAID matrices, text searches, and project dashboards requires fast indexed queries.

## Context and Problem Statement
Replaying millions of events sequentially on every CLI query or dashboard view would incur excessive I/O and latency. However, maintaining mutable indexes alongside an event log introduces the classic distributed systems risk of cache invalidation drift and dual-write corruption. We must define the relationship between the canonical event log and all secondary query indexes.

## Decision Drivers
- High-performance relational queries, filtering (e.g. "show all open blocker issues across all active projects"), and full-text search.
- Zero risk of split-brain: derived indexes must NEVER become a shadow source of truth.
- Frictionless disaster recovery: indexes must be completely disposable and re-indexable on demand.

## Decision Outcome
Chosen Solution: **Disposable Secondary Projections with Guaranteed Full Rebuildability**.

### Index Architecture:
1. **Materialized Snapshot Cache:**
   - Path: `.power/projects/<project_id>/snapshot.json`
   - Role: Latest rolled-up domain projection of `Project`, current active phase, unresolved RAID items, current RACI matrix, and DoR/DoD status.
   - Guard: Annotated with `last_applied_sequence` and `last_applied_event_hash`.
2. **Global Cross-Project SQLite Query Index:**
   - Path: `.power/project-state/indexes/project_state.sqlite3`
   - Role: Relational tables with foreign keys and SQLite FTS5 virtual tables indexing projects, phases, risks, assumptions, issues, dependencies, and RACI roles.
   - Invariant: Read-only for domain consumers; updated strictly by the PSE projection projector.
3. **Materialized Human-Facing Vault Markdown:**
   - Path: `<project.vault_path>/status.md` (contract-driven vault path, resolved dynamically from project metadata)
   - Role: Rendered read-only markdown summary for Obsidian viewing.
   - Status: Annotated with comment `<!-- GENERATED BY POWER PSE - DO NOT EDIT MANUALLY -->`.

### Rebuild and Reconciliation Contract:
- **`rebuild_from_events(project_id)` & Global Projection Rebuild Protocol:**
  PSE implements deterministic replay routines with explicit subsystem dependency semantics:
  1. **PSE-Only Projection Rebuild:** If `project_state.sqlite3` or `snapshot.json` contains solely PSE-owned data (project lifecycle, RAID, RACI, gate evaluations, relations), rebuilding from `.power/projects/<project_id>/events.jsonl` alone is valid and complete.
  2. **Federated Multi-Subsystem Index Rebuild:** If the global index also projects composite views including task details and decision statuses, the rebuild routine is strictly required to read from all three authoritative sources:
     - PSE event ledgers: `.power/projects/<project_id>/events.jsonl`
     - TaskStore: `.power/tasks/<task_id>.json` & `.power/tasks/events/<task_id>.jsonl`
     - DecisionService: `.power/tasks/decisions/<decision_id>.json` & `.power/tasks/decisions/receipts/<receipt_id>.json`
  3. **Deterministic Replay Loop:** Scans from `sequence = 1`, replays every event through the deterministic state reducer, flushes the verified snapshot, and updates SQLite tables.
- **Index Corruption Recovery:**
  Deleting the directory `.power/project-state/indexes/` or any `snapshot.json` will result in zero data loss. The runtime detects missing derived data on boot and automatically triggers multi-subsystem index regeneration.

## Consequences
### Positive
- Blazing-fast sub-millisecond query latency for dashboard and CLI filtering.
- Complete freedom to alter SQLite schema, add indexes, or change full-text search strategies across framework versions without migrating canonical project data.
- Absolute integrity: the canonical event ledger remains the single authoritative anchor.

### Negative
- CPU overhead during full rebuilds of large vaults (mitigated by checkpoint snapshots and sequential incremental catch-up).
