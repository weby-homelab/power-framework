# ADR 0004: POWER 3.7 Application API v2, Task Manager v2, and POWER-GUI Architecture

**Status:** Accepted

**Date:** 2026-08-13

## Decision

POWER 3.7 establishes a clear application boundary separating the core storage plane from human-facing and protocol interfaces:

1. **Human-owned Markdown and Git** remain the absolute source of truth and authority. No UI, federation node, or external agent may directly mutate files without creating a structured proposal, passing human approval, and receiving a content-free audit receipt with verifiable postconditions.
2. **Application API v2** in `power_framework.core.application` is the single entry point for all presentation and transport layers (CLI, MCP, POWER-GUI, Federation, A2A). It provides versioned DTO envelopes (`power.application.v2`) and strict path containment.
3. **POWER Task Manager v2** is canonical and durable within the vault (`.power/tasks/`), with immutable event streams, monotonic revisions, optimistic concurrency, and formal state transitions (`backlog`, `ready`/`submitted`, `working`, `input-required`, `auth-required`, `blocked`, `completed`, `failed`, `canceled`, `rejected`).
4. **POWER-GUI** is hosted in a separate repository (`projects/POWER-GUI`) with its own dependency lifecycle, strict Content Security Policy (CSP), sanitization, session security without hardcoded default credentials, and WCAG 2.2 AA accessibility. It acts purely as a presentation BFF (Backend For Frontend) communicating with POWER exclusively via `ApplicationService`.

## Consequences

- Direct file writes (`open(..., "w")`) in UI routes are strictly forbidden.
- In-memory ephemeral tasks are eliminated; all tasks are durably tracked with immutable receipts.
- Core `power-framework` remains independent and does not depend on FastAPI or UI web assets.
